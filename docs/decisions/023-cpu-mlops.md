# CPU難易度の段階的な自己改善

ユーザーは各難易度の「ちょうどよさ」を継続的に改善したい。試合の勝敗だけではプレイヤーの経験差を区別できず、アンケートだけでは回答者が偏るため、匿名の全CPU戦結果と任意の体感回答を併用する。人の回答は学習信号、人が編集できるポリシーは制約と停止手段にする。

現状のCPUは規則ベースで、行動選択に使う判断間隔が難易度ごとに異なる。初期段階で自動更新するパラメータは判断間隔に限定する。採掘量、資源、城HP、施工費用、行動規則は変更しない。モデルの版はCPU設定から算出し、旧版の試合を新版の評価へ混ぜない。

毎日の運用ジョブは、試合・アンケートの収集、必要件数とクールダウンの判定、勝敗と体感の方向照合、上下限内で1段階の候補生成、シード固定の左右入れ替えCPU戦、既存テスト・ビルド、設定と集計要約のコミット、Pagesへの公開を行う。データ不足、信号矛盾、制約違反、シミュレーション不合格、CI失敗時には公開設定を維持する。生データはGitHubに送らない。

これは既存ゲームのコスト内で運用できる小規模MLOpsであり、対局中にリアルタイム学習する方式ではない。将来、十分な人間対局データと安全な検証環境が整えば、行動方策そのものの学習を別段階として検討する。
