# Reference-driven 3D asset pass

The Google Drive sheets linked in `docs/references/manifest.json` are the art direction for Bot, castle, construction vehicles, and bridges. The resource sheets in the same Drive folder define soil, stone, and iron. The editable source is `assets/blender/infra-rush.blend`; `assets/blender/build.py` rebuilds and exports each scene to `public/models/*.glb`. Blender's graphical application was used to run and inspect the rebuild. `assets/blender/render_qa.py` renders isolated previews into `docs/qa/assets/` for comparison against the sheets.

The first pass emphasizes the silhouettes visible from the game camera: Bot proportions and safety vest; castle domes, battlements, gate, and flags; vehicle cabin with seated Bot, orange engine cover, tracks or wheels, and distinct excavator bucket, dozer blade, grader blade, launcher truss, and drill; stone and steel bridge details. Resource piles and the world sheet's mine cart, timber crate, and white flowers are also Blender assets. The construction parts stay separate for runtime motion. The continuous bridge deck and resource piles replace visibly generic geometry in the running game. The runtime resolves Blender's numbered object names so the Bot limbs and machinery hinges still animate after export.

These are deliberately low-poly, material-colored models because the game must remain usable on mobile browsers. The isolated previews and the live game camera are both required for review: the game camera makes some fine parts less legible than the design sheets, and further per-object art review is still needed before claiming exact sheet parity. Android and iOS physical devices are not connected to this workspace, so mobile visual inspection here uses the browser's phone-sized viewport; the user will check the local URL on their own devices.
