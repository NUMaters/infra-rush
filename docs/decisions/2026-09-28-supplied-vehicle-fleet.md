# 提供された重機モデルのゲーム採用

提供されたブルドーザー、モーターグレーダー、掘削機、架橋機の Blender / GLB を原本のまま保存し、ゲーム用の別ファイルを作る。Drive の各デザインシートと形・色を比較したうえで、既存の汎用モデルと置き換えた。

- 車体、ブレード、ドリルアームと先端、架橋機の桁と支持脚を独立した階層に分けた。元のメッシュ形状と塗装テクスチャは維持し、施工モーションは Three.js の状態と進捗に合わせて動かす。
- キャビンの該当ガラス面を半透明にして、搭乗する Bot が見えるようにした。赤チームは青い塗装領域のみ差し替えた専用 GLB を使う。白・黄・オレンジの部品とガラスは共通。
- 提供ファイルの金属度・粗さマップはゲームの柔らかい照明下で濡れたように光るため、車体の金属度を 0.035、粗さを 0.57 に固定した。ドリル先端は金属度 0.38、粗さ 0.40、窓は粗さ 0.18 とする。
- 大きな彫刻メッシュだけを簡略化して輪郭を保った。4台の青版は各 6.3〜6.9 MB。読み込み時間と実機 GPU 負荷は今後も測定し、必要ならテクスチャ圧縮や遠距離 LOD を行う。

原本は各 `assets/vehicles/*/source/supplied-*`、編集可能なリグは同フォルダの標準 `.blend`、配信用 GLB は `public/models/` に置く。生成手順は `assets/blender/build_all.sh`。デスクトップとスマホ寸法の E2E で4工種と赤チーム掘削を確認した。実機 Android / iOS の最終確認は端末未接続のため未実施。

追補: 桁の伸長は架橋機のローカル X 軸（車体前方）で行う。旧実装の Z 軸では車体横方向に移動していた。ドリルの回転支点は先端の下向き傾斜に合わせて約 28 度傾け、元の姿勢を保ったまま支点のローカル X 軸で回す。青・赤の4工種すべてについて、実際に作業中のモデル名、桁先端の移動方向、ドリル軸の安定性を E2E で確認する。PWA キャッシュも更新し、赤チーム用 GLB をオフライン保存の対象に含める。
