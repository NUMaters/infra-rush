## 性能の観測範囲

MacのCodexブラウザ、スマホ幅で約57fps、描画283 calls / 165,434 triangles、JSヒープ約47MBを1回観測。初回タイトルで約60fpsも観測。全端末60fps、ピーク負荷、長時間メモリ安定性を保証する測定ではない。フレーム時間にはシミュレーションのdt上限ではなく実経過時間を使用。

GLBの最新サイズ・三角形数は `../../public/models/manifest.json`。モデルは共有ジオメトリ・チーム別材質キャッシュを利用し、植生と小物はインスタンシング。パーティクルもジオメトリと材質を再利用。

## 見つかった問題と修正

- UIを毎回再生成してボタンがクリック途中で消える → Bot/作業パネルはHTML変更時だけ更新。
- 資源獲得エフェクトにHUDカードのスタイルが混入 → CSSクラスを分離。
- マテリアルが白っぽい → BlenderのsRGB指定をlinear値へ変換。
- ヘルメットの中央突起が埋もれる、ベストの形状・反射帯 → 原画とGLBレンダーを比較して修正。
- 城の周囲が孤立した柱に見える → 側壁・背面の石積みを接続。
- グレーダーのブレードが小さい → 横幅と油圧部を修正。重機に下部ドアと操縦ハンドルを追加。
- 整地時に盛土が突然消える → 完了まで高さが連続的に減る。
- サブディレクトリでモデルが404になる絶対パス → 文書URLを基準にした相対パス。
- 起動失敗をすべてWebGLの問題と表示 → データ読み込み失敗と3D初期化失敗の案内を分離。

## 失敗の記録

端末上で依存ファイルの読み込みが数分以上停滞し、`Unknown system error -70: read`、出力ファイルの`operation timed out`も発生。npm初回インストール、Lint、ビルドで失敗後、再試行により成功した。

最初のE2Eはタイトルの5秒待ちで失敗し、一部は45秒のモデルロード期限にも到達。モデル応答自体はHTTP200でも完了できない実行があった。失敗例は `e2e-first-load-failure.md`。テストのタイトル待機を60秒に設定した後、4件が合格。時計停止中は3D直接選択も止まるため、直接選択確認後に検証時計を停止するようテストを修正。

Python標準HTTPサーバーでもファイル送信中にタイムアウトを観測。ローカル確認用に `scripts/serve-preview.py` を追加し、起動時に静的ファイルを読み込んで以後メモリから配信。これで配布用画面の起動を確認した。公開ホスティングの性能を示すものではない。

## 実機確認手順

同じネットワークで `http://172.20.10.2:5177/`。Mac側は `http://localhost:5177/`。IPは接続ネットワークで変わる。

1. 「はじめて」で開始し、5体すべてに採掘を指示。
2. 石50以上で1体に「橋をつくる」を指示。
3. 開通後に進軍し、1ダメージ・帰還を確認。5回で勝利。
4. 音声・拡大縮小・遊び方・一時停止・再戦を確認。
5. 端末名、OS/ブラウザ、気づいた操作しづらさ・表示崩れ・遅さを記録。

サーバー再起動は `python3 scripts/serve-preview.py --directory dist --port 5177`。ファイル変更後はサーバー再起動が必要。
